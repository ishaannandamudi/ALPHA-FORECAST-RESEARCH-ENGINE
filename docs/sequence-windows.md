# Exact sequence windows

`SequenceWindowSpec` pins origin-cutoff anchor, mode, maximum/minimum observations, lower/upper inclusion, padding, revision policy, exact-vintage roster, ordering, alignment, time encoding and implementation. `FIXED_OBSERVATION_COUNT` selects the latest N distinct admissible timestamps after causal filtering and revision resolution. Its N is a timestamp count; individual features can have fewer effective tokens. `ELAPSED_DURATION` applies the exact supplied duration in UTC nanoseconds and then the declared count cap. All four lower/upper boundary combinations are supported. Session windows and grid alignment are unsupported; no inferred trading calendar or informal date subtraction is used.

Default elapsed semantics are `(T-L,T]`, anchored at `ForecastOrigin.availability_cutoff_ns`. Availability filtering precedes revision resolution, so a later correction cannot replace an earlier historically available vintage. Revisions are grouped by exact sequence feature and observation timestamp. `LATEST_AVAILABLE_REVISION` chooses maximum `(final availability, upstream revision artifact ID, sequence observation fingerprint)`. Equal-time revisions thus have a deterministic identity tie, not an inferred provider revision number. `FAIL_ON_MULTIPLE` rejects multiple admissible revisions; `EXACT_VINTAGE` requires the exact canonical candidate roster and one vintage per semantic observation.

Selected timestamps increase strictly. Features have canonical fingerprint order; alignment is the exact timestamp union with per-feature masks. Candidate IDs and exclusion reasons are retained for audit; excluded values never enter the numerical window. Automatic queries include only candidates whose final historical availability and actual AFRE processing-ready clock are at or before snapshot construction. Explicit candidate rosters enforce both construction floors, including qualified reconstructions whose historical final availability predates actual receipt/ingestion/computation. A retrospectively constructed snapshot can document observations unavailable at its earlier origin, but its later construction/availability is retained and it cannot issue a backdated forecast. Corrected source publication creates new identities; rebuilding is explicit and never mutates old snapshots.

Hard limits: 128 timestamps, 16 features, 100,000 registered observation candidates. Per-repository limits may only reduce these. Observation queries use explicit security/feature constraints, deterministic order and LIMIT+1 overflow rejection. [Mask rules](sequence-masking.md).
