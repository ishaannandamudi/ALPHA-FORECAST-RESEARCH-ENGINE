# Service reproducibility and causality

Public artifacts reuse closed AFRE canonical JSON, integer UTC nanoseconds, finite-float rules and domain-separated SHA-256. Nonfinite numbers, duplicate fields, executable metadata and arbitrary class names fail closed. The public decoder accepts service roots only. No pickle, shell, runtime network, executable plugin or provider-selected paths are used.

A frozen read validates native source output semantics, exact compatible context projections, contributor registrations and public projections. A valid new hash alone does not admit a forged output/context/registry/audit/lineage. Independent semantic replay must agree. Source publication and context inclusion are append-only; exact republish is idempotent. Restart, hash seeds 0/1/42/random, reversed sources/requests/contexts/registry entries/horizons and concurrent publication preserve semantic bytes.

The service guard rejects TargetVintage and later outcome records before get/resolve/get_any caches. Forecast lineage traverses bounded feature/source evidence and target definitions while treating fitted TRAIN artifacts, dataset input-build certificates and historical evaluation metadata as opaque leaves. It never reads held-out truth or future target bars. The public audit pins the complete snapshot, exact snapshot registration, versions, lineage, limits and descriptive/manual action boundaries.

RECORDED_CAUSAL means native receipt/computation evidence supports the origin. QUALIFIED_RECONSTRUCTED is used only when the used feature/source evidence contains an existing qualified historical delivery contract. Actual AFRE receipt/ingestion/computation clocks remain intact; upstream publication alone never backdates system availability. A live feature published at 10:00 and received at 10:02 is unavailable at 10:01. An archive downloaded months later requires qualified historical delivery evidence to establish earlier causal availability.

The deterministic offline demo and measured profile are `examples/service_demo.py` and `benchmarks/service_profile.py`. Measurements are bounded offline research diagnostics, with no production SLA or trading profitability claim.
