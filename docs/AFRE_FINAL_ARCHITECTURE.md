# AFRE final architecture

Engine 1.0.0 completes 26 distinct phases, AFRE-0 through AFRE-25. API and all public schemas are 1.0; store 1.24 / SQLite user_version=25; Python 3.11+; zero runtime dependencies. The release decision is recorded in [the final report](AFRE_25_COMPLETION_REPORT.md).

The causal path is stable security/universe evidence → six-clock feature vintages → exact target definitions and separately available labels → leakage-safe datasets/folds → TRAIN-fitted artifacts → target-free predictions → optional calibrated/event/filtered-regime/uncertainty/rank/orthogonal/fused evidence → immutable public snapshots and frozen registry catalogs. VALIDATION supplies declared finite selection and comparative research; TEST is sealed, post-selection evaluation evidence. Descriptive health and MANUAL_ONLY challenge metadata never change an active model.

AFRE-18 evaluates hypothetical transaction costs separately from portfolio construction. AFRE-19 accounts for research opportunities, failures, multiplicity and TEST reuse. AFRE-20 selects finite declared candidates separately from AFRE-21 ensemble construction. AFRE-22 describes drift and decay separately from AFRE-23 matched champion/challenger evaluation. AFRE-24 is the final service boundary; AFRE-25 audits it. There is no subsequent roadmap phase.

Native contracts retain schema 1.0. The package adds only a closed service version compatibility catalog and recorded-version semantic replay. No earlier model implementation or persisted schema is redesigned. Separate bounded native workflows cover service/model families and the feature→fit→forecast→fusion→snapshot correction chain. Existing selection, multiple-testing, invariance and cost workflows provide independently tested research boundaries.

The stable public entry point is `afre.service`; the administrative publisher is explicit and separate from the read-only consumer protocol. Downstream systems own portfolio construction, risk optimization and execution. See [API](AFRE_PUBLIC_API.md), [handoff](AFRE_INTEGRATION_HANDOFF.md), [temporal audit](AFRE_TEMPORAL_AUDIT.md) and [research audit](AFRE_RESEARCH_AUDIT.md).

The audit also fixes native research staging on later stores: selection and fusion trial registration retain the concrete repository layout and configured bounds in frozen copies. Their publication remains limited to the existing immutable native tables. Final-store regression tests exercise actual selection and fusion trial registration; earlier phase tests preserve original behavior.
