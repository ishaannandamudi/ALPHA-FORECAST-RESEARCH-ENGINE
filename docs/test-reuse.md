# TEST reuse visibility

Every completed TEST trial pins exact existing native TestEvaluation seals that cover
its TEST sample set, fold and evaluation cutoff. New assessment creation requires an
explicit assessment identity and a frozen caller-attested predeclared opportunity.
Retrospective audit uses existing seals; validation-only trials cannot attach TEST seals.
Both paired sides contribute to TEST admission, and evaluation is frozen inside the
same read snapshot before seal/trial/raw/effect atomic publication.

A policy pins an explicit heavily-reused threshold (3..2000), declared before the trial.
Counts come from exact registry membership and the dataset/fold/target/horizon/metric
scope. Every registered sealed attempt counts, not only successful/significant winners.
Exact seal IDs/counts are retained. Different seal names on the same scope do not reset
research opportunity counts.

FIRST_USE=1, REUSED=2..threshold-1, HEAVILY_REUSED>=threshold; validation-only is
INCOMPATIBLE. A separate tracked_status preserves those counts when native assessments
not linked to any registered trial make global status UNTRACKED. AFRE cannot prove that
no other human research used the holdout. Older registry/reuse diagnostics never expand
when new attempts are appended.

TEST cannot choose family membership, direction, metric, null, alpha/q, correction
reports or a preferred registry subset. Timestamps and seals are semantic evidence,
not authentication or proof of human preregistration. AFRE20 TRAIN/VALID selection
remains deferred. See [families](hypothesis-families.md) and [registry](research-trial-registry.md).
